Week 2 Questions:

  1. When is it more feasible to use application containers than full OS virtualization?
  2. Compare application containers to microservices
  3. Describe shortly what is Kubernetes and what alternatives are there?
  4. List some information security risks when using third-party containers?

Answers:

  1. Containers are faster to boot up than Virtual Machines and are more lightweight allowing for more apps in a single server. VMs offer stronger isolation and security which is useful for multi-OS environments and legacy applications.
  2. Containers are as its name implies packages which are used for consistent excecution across environments, where as microservices are an architecture of different small services. Microservices and containers are usually used together for efficient scaling and speed compared to microservices and VMs.
  3. Kubernetes is effectively a container manager which helps containers run smoothly and efficiently. It restarts crashed containers, balances network traffic and scales resources depending on load. Other alternatives include AWS ECS, HashiCorp Nomad and Docker Swarm which all include their own benefits and downsides.
  4. Containers are weak to supply chain attacks where a malicious actor uploads for example a web server to Docker Hub which contains a crypto-miner or malware. If you download a base image which is behind software updates, it could have unpatched vulnerabilities. There are dozens of ways hackers can breach your container from root access, docker sockets, accidental key leaks. Though the usual vigilance in your own security measure are enough.

Week 3 questions:

  1. What would a mid-size company store to the Amazon Glacier? What not? Why? What other large cloud backup or mass storage providers are there?
  2. Select and describe 2-3 well-known Amazon S3 data leak incidents. What went wrong? List some automated S3 bucket search engines and attack tools (don't try the tools, illegal!)
  3. Your thoughts about when to maintain your own web server and when to use SaaS/PaaS/IaaS to provide web services?
  4. Describe reasons, why many IoT devices (internet connected home appliances, Smart-TVs and such) are using Google's 8.8.8.8 or some other public DNS resolvers?

Answers:

  1. A company could use it for long-term backups, legal compliance logs, or old raw media files. They would not store anything relevant or something that would need to be pulled often there because retrieving data from Glacier can take hours. Alternatives include Google Cloud Coldline and Azure Archive.
  2. 2025 Codefinger Ransomware Attack, A group exploited compromised AWS credentials to encrypt S3 data using SSE-C, demanding ransom from multiple organizations. 2024 vpnMentor Discovery, A large-scale operation scanned millions of sites, using misconfigured S3 buckets as a "shared drive" to exfiltrate sensitive keys and customer data. The 2025 leak was caused by compromised long-lived AWS access keys and the 2024 leak was an application-level misconfigurations on customer public-facing websites. Some well known automated S3 bucket search engines and attack tools are: Grayhat Warfare, BuckHacker, Censys and Shodan
  3. You should maintain your own web server when you need absolute physical control over the hardware, have strict data residency laws, or have a predictable workload where buying hardware is cheaper than monthly cloud fees. You use PaaS when you want to focus purely on development and let the provider handle OS updates, networking, and scaling.
  4. Using a public DNS like Google's or Cloudflare's (1.1.1.1) provides better privacy and can bypass local ISP censorship. The downside is CDN routing issues. Content Delivery Networks use your DNS resolver's location to send you to the closest server. If you use a Google DNS server far away from your house, the CDN might route you to a slower, distant server.
