Questions:

  1. When is it more feasible to use application containers than full OS virtualization?
  2. Compare application containers to microservices
  3. Describe shortly what is Kubernetes and what alternatives are there?
  4. List some information security risks when using third-party containers?

Answers:

  1. Containers are faster to boot up than Virtual Machines and are more lightweight allowing for more apps in a single server. VMs offer stronger isolation and security which is useful for multi-OS environments and legacy applications.
  2. Containers are as its name implies packages which are used for consistent excecution across environments, where as microservices are an architecture of different small services. Microservices and containers are usually used together for efficient scaling and speed compared to microservices and VMs.
  3. Kubernetes is effectively a container manager which helps containers run smoothly and efficiently. It restarts crashed containers, balances network traffic and scales resources depending on load. Other alternatives include AWS ECS, HashiCorp Nomad and Docker Swarm which all include their own benefits and downsides.
  4. Containers are weak to supply chain attacks where a malicious actor uploads for example a web server to Docker Hub which contains a crypto-miner or malware. If you download a base image which is behind software updates, it could have unpatched vulnerabilities. There are dozens of ways hackers can breach your container from root access, docker sockets, accidental key leaks. Though the usual vigilance in your own security measure are enough.
